# Run and operate Laya Local

For first installation, see [the README](../README.md#quick-start). Commands below run from the project root in PowerShell.

## Everyday commands

```powershell
cd C:\Users\richd\Documents\oMAR\Laya
.\start.ps1 -OpenBrowser
```

Open http://localhost:8000 and enter `LAYA_API_KEY` from `.env`. Startup prints this PC's LAN addresses too. The service starts manually; restarting Windows does not start it automatically.

```powershell
# Stop the process managed by this checkout.
.\stop.ps1

# Alternatively, keep logs in the terminal; stop with Ctrl+C.
.\start.ps1 -Foreground

# Inspect background logs without printing credentials.
Get-Content .\logs\service.err.log -Tail 60

# Public liveness check; this does not load a checkpoint.
Invoke-RestMethod http://localhost:8000/health
```

`start.ps1` refuses an occupied port. Check the existing portal before starting another instance. `stop.ps1` verifies the recorded process belongs to this checkout, requests shutdown and releases the service's GPU allocations. Windows may show a parent launcher and a child Python process for the virtual environment. Foreground sessions are stopped in their own terminal.

`/health` reports process liveness. Authenticated `/api/v1/status` and **Models & GPU** report readiness, resident checkpoint, outstanding jobs, memory and errors. An idle service can be ready with no checkpoint loaded.

## Keys and settings

| Setting | Purpose |
|---|---|
| `.env`: `LAYA_API_KEY` | Shared bearer key for this installation. Generated by setup; never commit it. |
| `.env`: `LAYA_HOST` | Listen address; `0.0.0.0` accepts connections on this PC's interfaces. |
| `.env`: `LAYA_PORT` | HTTP port, default `8000`. |
| `.env`: `LAYA_ALLOWED_HOSTS` | Comma-separated extra hostnames/IPs for MCP host/origin validation. |
| `data/settings.json` | Saved default model, initially `auto`; managed by the service. |

Restart after editing `.env`. After changing the key, reconnect each tab/client. The portal uses session storage scoped to the tab, not persistent local storage. Input and result data stays in browser memory unless exported.

In **Models & GPU**, **Use as default** persists a named checkpoint only after successful loading and placement checks. Selecting `auto` saves routing mode without loading every model. An explicit Playground/API model overrides the setting for that request only. The shared default affects other clients too.

## GPU and model switching

Only one checkpoint is resident at a time. The service unloads the previous checkpoint before loading the next and serializes GPU work. First initialization and checkpoint switches add loading time; compact warm inference is much faster. Batch related decisions using the same checkpoint to avoid repeated switches.

The production adapter requires CUDA inference. GPU failures return errors; it does not retry inference on CPU. Other applications can reduce available VRAM. A multilingual limit of 8,192 tokens is a supported ceiling, not a guarantee that every request will fit available memory.

Inputs, questions, options and formatting share the total token budget. Read `usage` and truncation warnings. See [model limits](models.md) and [error response details](api.md).

## Use it on your local network

1. Start the service on this PC. Use a LAN address printed by `start.ps1`, for example `http://192.168.1.20:8000`.
2. If Windows blocks access, run `.\enable-lan.ps1` once from an elevated PowerShell window in this checkout. The rule permits the configured port from `LocalSubnet`; it does not open public internet access.
3. Open that address from the trusted device and use the same key. MCP clients use `/mcp/`. If using a custom hostname, add it to `LAYA_ALLOWED_HOSTS` and restart.

The firewall script needs elevation because it changes a Windows firewall rule. It does not change network profiles. Access from a second device must be checked on your own network; a request to this PC's LAN address from this PC is only a local reachability check.

Third-party browser origins have no CORS access. Server-side apps can make authenticated HTTP calls. Container localhost means the container, so configure a reachable host/LAN address. Cloud agents cannot reach this PC's localhost without a network path. This deployment assumes a trusted LAN and plain HTTP; public hosting is outside its scope.

## Troubleshooting

| Symptom | Check or action |
|---|---|
| `401` | Match the current `.env` key and send `Authorization: Bearer <LAYA_API_KEY>`. Reconnect the portal after key changes. |
| Busy / `Retry-After` | Wait the indicated time and retry with bounded backoff. Eight outstanding jobs share one worker. |
| Long first request | Check **Models & GPU** and logs. Allow loading time; avoid repeatedly switching checkpoints while it loads. |
| CUDA unavailable / GPU memory error | Inspect `nvidia-smi`, close competing GPU workloads, lower the multilingual context budget, then retry. No CPU inference fallback is available. |
| Input validation error | Inspect the documented error and OpenAPI schema. Fix question types, options, model names or budgets before retrying. |
| Truncation warning | Reduce the state/questions or choose an appropriate supported limit; discarded evidence may change the answer. |
| Missing checkpoint | Serving is offline. Rerun setup with network access to download the pinned artifacts; requests do not download models. |
| Frontend missing | Run setup or rebuild using the [development guide](development.md), then restart. |
| Port occupied | Open the existing service and inspect its ownership. Stop this checkout's managed service before restarting it. |

`setup.ps1` is repeatable and uses the locked Python environment plus `npm ci`. `setup.ps1 -SkipModels` skips downloads when weights and `.env` already exist; it is not a replacement for initial setup. It checks for 10 GiB free disk space before installation.

## Local files

Weights/cache, `.env`, logs, browser test artifacts and raw verification outputs are ignored by Git. Exported inputs/results are your responsibility. Public `/llms.txt`, Markdown guides, OpenAPI and model metadata contain generic integration/learning information; protected runtime endpoints and private benchmark inputs require the key.
